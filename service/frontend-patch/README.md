# Подключение фронтенда к конвейеру

Фронтенд (`pto-drawings`) — чужой репозиторий, поэтому патч лежит здесь, а не
применён к рабочей копии. Меняется **один файл**.

## Почему только один

Интерфейс уже умеет всё, что нужно для потоковой загрузки: показывает
`готово/всего`, процент, текущий лист и шаг, держит состояние в `db.json`
(переживает F5), опрашивает статус каждые 900 мс, позволяет добавлять файлы
во время работы очереди. Менять UI не требуется — достаточно подменить
источник страниц.

Файл `process-document.ts` экспортирует ту же функцию `processDocument(id)`,
что и оригинал, поэтому маршруты `api/documents/route.ts` и
`api/documents/[id]/process/route.ts` править не нужно.

Отдельно: шапка каждого листа от бэкенда содержит строку `**Файл:**`. Это не
украшение — `storage.ts:listDocuments()` перегенерирует markdown заглушкой из
`extractedText`, если этой подстроки нет, и молча затирает результат прогона.
С шапкой блок не срабатывает, править `storage.ts` не приходится.

## Применение

```powershell
cd <корень проекта>\frontend\pto-drawings
copy src\lib\process-document.ts src\lib\process-document.unpdf.ts.bak
copy ..\..\backend\service\frontend-patch\process-document.ts src\lib\process-document.ts
```

Откатиться — вернуть `.bak` на место.

## Запуск связки

Два процесса на одной машине.

**1. Бэкенд** (`backend/`), обязательно с доступом к папке загрузок фронта:

```powershell
cd <корень проекта>\backend
$env:PTO_PIPELINE_MODE = "mock"   # для проверки интеграции; real — настоящий прогон
$env:PTO_ALLOWED_PDF_ROOTS = "<корень проекта>\frontend\pto-drawings\uploads"
python -m service
```

**2. Фронтенд** (`frontend/pto-drawings/`):

```powershell
npm install        # первый раз
npm run dev        # http://localhost:8080
```

PDF между процессами не пересылается: фронт кладёт файл в свой `uploads/`, а
сервис читает его оттуда по пути. Поэтому `PTO_ALLOWED_PDF_ROOTS` обязателен —
без него сервис ответит 403 на попытку взять файл извне разрешённых каталогов.

Если бэкенд слушает не на `127.0.0.1:8000`, укажите фронту адрес:
`PTO_BACKEND_URL=http://хост:порт`.

## Что проверять

1. Загрузите PDF — документ встаёт в `queued`, затем `processing`.
2. Листы появляются по одному, счётчик `n/N` и процент растут.
3. Обновите страницу браузера в середине прогона — прогресс не теряется.
4. Загрузите второй файл, пока считается первый — он ждёт своей очереди.
5. Перезапустите бэкенд на середине — прогон продолжится, готовые листы не
   пересчитываются.

## Чего пока нет в интерфейсе

Это отложено до правок UI в форке:

- кнопка отмены (API готов: `POST /jobs/{id}/cancel`);
- предупреждение, что в режиме `real` страницы уходят стороннему провайдеру;
- расход токенов (сервис отдаёт его в `usage`).
