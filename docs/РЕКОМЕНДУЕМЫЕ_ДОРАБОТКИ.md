## 1. Чинить в DWG (основной путь)

Один цикл — один вопрос. В пользовательский текст по-прежнему только уверенные совпадения.

### 1.1. Стык скважин и проб с легендой

На КР1 **76** вставок (`CPE`, `CME`, `CCE`, `CGE`, `PR_KV`, `PR_VD`) видны, строки легенды про скважину и пробы есть, отпечаток блока другой.

Имеет смысл: сопоставить тип блока на поле со строкой легенды (не с ГОСТ), подписать хотя бы «скважина / образец / проба» без выдумки номера. Номера СКВ — отдельно, если они не в том же блоке.

Не имеет смысла: поднимать их в `confirmed` грунт или смешивать с кружками ИГЭ.

### 1.2. Штрих слоя

160 заливок. **34** ошибочно повешены на строку УГВ; **126** без имени грунта.

Сначала снять ложную привязку к УГВ. Затем искать стык заливки с образцом грунта в легенде (паттерн / слой), не «ближайший кружок».

Не имеет смысла: красить штрих именем ИГЭ с кружка рядом — кружки стоят столбиками скважин.

### 1.3. Словарь легенды

Две склейки, не ломающие кружки, но портящие ключ:

- заголовок «ГРАНИЦЫ» не считать знаком;
- УГВ отделить от «дата замера».

Почвенный слой и песок средней крупности без кружка в индекс проекта не тащить, пока нет своего `blockdef`.

### 1.4. Служебные блоки — не очередь знаков

**21** вставка `LinkedData` / `0_dim` (`_ИГЭ`, `УгвДата`, подписи составителя…) сейчас в «нераспознанных». Их лучше отфильтровать как служебные, как оси и отметки: не грунт и не скважина.

### 1.5. Остальные ИГР того же типа

КР3 уже с каталогом КР1 (**159** кружков). Дальше — КР2 и КР4 тем же правилом: легенду не читать заново, только поле. Старый срез `review_ideal_igr` не использовать.

Планы КР/ТХ — свой словарь, новый срез, не в этот цикл.

## 2. VLM как дополнение, не замена

Цифры штампа, подписи легенды и кружки ИГЭ модель **не перечитывает**. Ответ VLM сам по себе **не** `confirmed` (на PDF `01.pdf` пять кропов легенды модель оставила неразрешёнными).

Имеет смысл только **кроп + закрытый вопрос**, не PASS-A на лист целиком.

| Задача | Как спрашивать | Куда класть ответ |
|---|---|---|
| Скважина / проба vs образец легенды | два кропа: «тот же знак / нет / не уверен» | очередь review; в отчёт — только если человек или устойчивое «тот же» |
| Штрих vs образец грунта в легенде | кроп заливки + кроп строки легенды | то же; не подпись кружка рядом |
| Пустые слоты «ИЗ ЧЕГО / КАК связаны» | кроп вида: схема скважин, сваи, состав окна | проза описания, не ведомость знаков |
| Номера СКВ, фундамент на картинке | кроп вида, не весь лист | описание; в `confirmed` не поднимать |
| Листы без DWG (ПБ, ОДИ, пожарка PDF) | позже, отдельный контур | описание листа, не классификатор знаков |

Правила, если включать:

- вопрос закрытый, не «опиши чертёж»;
- «не уверен» = пропуск;
- имена грунтов и числа в отчёте остаются из sidecar;
- не звать модель, чтобы дописать «под осью N» или ГОСТ.

Не имеет смысла: целый лист одним вопросом (петли, путаница чисел); пересказ как ИДЕАЛ вместо инвентаря; генплан ПЗУ без `_Ссылки` (на preview пустая рамка).

## 3. Спросить составителя (не код)

Пока нет ответа — поле в отчёт не выдумывать.

1. Слой «под осью N» они читают по марке сверху, по скважине или никак? Без ответа стык по x и линию оси не делать.
2. Какой файл — мастер легенды по теме (геология уже КР1; планы / сети — свои).
3. Будут ли DWG ПБ, ОДИ, АР или только PDF.
4. Пакет `_Ссылки` для ПЗУ.
5. Каким ГОСТ / альбомом бюро реально пользуются — только справочник, не классификатор сейчас. Подробности: [`ПРЕПЯТСТВИЯ_РАСПОЗНАВАНИЯ_ГОСТ.md`](ПРЕПЯТСТВИЯ_РАСПОЗНАВАНИЯ_ГОСТ.md).

## 4. Не делать этими доработками

- Сборщик отчёта «как будто критерий по оси закрыт»; сессия «кружок → ближайшая ось».
- Классификатор ГОСТ; повтор разбора PDF `01.pdf`; один словарь на 94 DWG.
- Смешивать геологию с ТХ/ПЗУ в одном срезе.
- Заполнять `expected` в манифесте выдумкой.
- Печать этого DWG в PDF «чтобы появилась ось» — линии в файле нет.
- Поднимать `probable` в ведомость.
