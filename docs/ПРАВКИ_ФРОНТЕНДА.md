## 8. Приём файлов `.docx`

**Файл:** `src/lib/drawing-files.ts`.

Бэкенд с 28.08 читает пояснительные записки `.docx`: текст и таблицы берутся
из файла как данные, без модели. Это половина каждого раздела — в комплекте
«Жуковский» шесть таких файлов, и раньше они не доезжали до сверки вовсе.

**Интерфейс их сейчас не пропустит:** `getDrawingExt` знает только `pdf`,
`dwg`, `dxf` и вернёт `null`, а маршрут загрузки на этом отвечает «У файла
должно быть расширение .pdf, .dwg или .dxf».

```diff
-/** Допустимые форматы чертежей: PDF и CAD (DWG/DXF). */
-
-export type DrawingExt = "pdf" | "dwg" | "dxf";
+/** Допустимые форматы: PDF, CAD (DWG/DXF) и записка DOCX. */
+
+export type DrawingExt = "pdf" | "dwg" | "dxf" | "docx";

 export function getDrawingExt(name: string): DrawingExt | null {
   const lower = name.toLowerCase();
   if (lower.endsWith(".pdf")) return "pdf";
   if (lower.endsWith(".dwg")) return "dwg";
   if (lower.endsWith(".dxf")) return "dxf";
+  if (lower.endsWith(".docx")) return "docx";
   return null;
 }
```

Дальше — три места, где формат перечислен явно:

```diff
 export function mimeForExt(ext: DrawingExt): string {
   if (ext === "pdf") return "application/pdf";
   if (ext === "dwg") return "application/acad";
+  if (ext === "docx") {
+    return "application/vnd.openxmlformats-officedocument.wordprocessingml.document";
+  }
   return "application/dxf";
 }

 export const DRAWING_ACCEPT =
-  "application/pdf,.pdf,.dwg,.dxf,application/acad,image/vnd.dwg,application/dxf,image/vnd.dxf,.zip,application/zip,application/x-zip-compressed";
+  "application/pdf,.pdf,.dwg,.dxf,.docx,application/acad,image/vnd.dwg,application/dxf,image/vnd.dxf,application/vnd.openxmlformats-officedocument.wordprocessingml.document,.zip,application/zip,application/x-zip-compressed";

-export const DRAWING_ACCEPT_HINT = "PDF, DWG, DXF или ZIP (PDF + DWG)";
+export const DRAWING_ACCEPT_HINT = "PDF, DWG, DXF, DOCX или ZIP (PDF + DWG)";
```

`isCadExt` трогать не надо — записка не CAD, у неё нет ни предпросмотра, ни
геометрии. `UPLOAD_HELP_LINES` можно дополнить строкой вроде «Пояснительная
записка .docx — текст и таблицы читаются из файла, без модели».

**Про старый `.doc`.** Бинарный формат Word бэкенд не читает и отвечает на
него понятным текстом с кодом 400: «Старый формат .doc не читается. Откройте
файл в Word и сохраните как .docx — текст и таблицы возьмутся из него как
данные, без модели». Этот текст приходит в поле `error` — его стоит показать
как есть, а не заменять общим «не удалось загрузить». В комплекте таких
файлов пять из одиннадцати, так что пользователь на него наткнётся.

**Мелочь рядом.** В `BackendPage` у вас `trust.level: "dwg" | "layer" | "vlm"
| "none"` — добавьте `"docx"`: у листа записки уровень доверия именно такой.
На поведение это не влияет (сравнение идёт только с `"vlm"`), но тип уже
неполон.

## 9. Сводный отчёт по комплекту

**Что есть на бэкенде.** Комплект сводится в один документ: листы всех файлов
раскладываются по разделам и документам **по основной надписи** — не по
именам файлов и не по номерам страниц. Лист, пришедший и из чертежа, и из
альбома, сводится в один: основа из DWG, потому что там текст лежит данными, а
из PDF добираются строки, таблицы и описание, которых в чертеже нет.

Расхождения между источниками выносятся отдельно, и с 28.08 сверка видит не
только реквизиты, но и **числа**: «Отметка низа фундамента −2.050» в чертеже
против «−2.150» в альбоме. Для ПТО это готовое замечание — значит альбом
печатали с другой редакции чертежа.

**Чего нет.** Интерфейс эти маршруты не вызывает вовсе, то есть для инженера
сверки не существует.

### Минимальная версия — час работы

Одна вкладка «Комплект» рядом со списком файлов проекта, один запрос, готовый
markdown. Рендерер у вас уже есть — тот же, что рисует лист.

```ts
// src/app/api/projects/[id]/report/route.ts — по образцу /api/pipeline/health
const response = await fetch(
  `${PIPELINE_URL}/projects/${encodeURIComponent(id)}/report?bodies=false`,
);
return new Response(await response.text(), {
  headers: { "Content-Type": "text/markdown; charset=utf-8" },
});
```

`bodies=false` отдаёт только состав, дубли и расхождения — быстро и без
содержимого листов. `projectId` — тот самый, что вы уже кладёте в `createJob`,
искать ничего не нужно.

### Полная версия — если делать по-хорошему

Три маршрута отдают то же самое структурой, чтобы расхождения можно было
подсветить, а не читать в тексте:

| Маршрут | Что отдаёт |
|---|---|
| `GET /projects/{id}/sections` | состав комплекта: разделы → документы → листы, с источниками каждого |
| `GET /projects/{id}/pages` | плоский список сведённых листов; `?bodies=true` — с содержимым |
| `GET /projects/{id}/pages/{sheetId}` | один сведённый лист: markdown и разметка блоков |

Реальный ответ `/pages` (лист из одного источника):

```jsonc
{
  "sheetId": "28-ХСА-1_25-КР1:17",   // годится как ключ и как маршрут
  "number": "17",                     // номер листа в комплекте, не страница файла
  "title": "Геологические разрезы по линиям XII-XII…",
  "code": "28-ХСА-1/25-КР1",
  "kind": "графическая часть",        // или «текстовая часть»
  "primarySource": "DWG",             // истина: DWG важнее PDF
  "variants": [{ "source": "разрезы.dwg", "kind": "DWG", "index": 1, "jobId": "…" }],
  "verifiedBy": ["DWG"],
  "conflicts": [],                    // ← вот это и надо показывать
  "ready": true
}
```

Элемент `conflicts` — это `[что, как в чертеже, как во втором источнике, имя
файла]`:

```jsonc
"conflicts": [
  ["наименование листа", "Фундаменты Ф-1", "Фундаменты Ф-2", "альбом.pdf"],
  ["числа в строке «отметка низа фундамента …»",
   "Отметка низа фундамента -2.050",
   "Отметка низа фундамента -2.150", "альбом.pdf"]
]
```

Лист с непустым `conflicts` стоит помечать в списке — это самая ценная строка
во всём отчёте.

**Про `skipped`.** В ответах есть поле `skipped` — файлы, которые прочитать не
удалось. Один битый чертёж не роняет отчёт по всему проекту, но сказать о нём
инженеру надо.

## Как проверить

**Пункт 8.** Загрузить любой `.docx` — он должен приняться, а лист прийти с
подписью «Авторазбор» и без «Проверки чисел» (модели не было). Затем
попробовать `.doc` — должно показаться сообщение бэкенда про пересохранение,
а не общая ошибка.

**Пункт 9.** Положить в один проект чертёж и PDF одного раздела; во вкладке
«Комплект» они должны встать в **один раздел** — графической и текстовой
частью, а не двумя отдельными документами.

## Что приходит от бэкенда

Схема страницы — 8.

```jsonc
GET /jobs/{id}/pages?pages=1,2,3   →   { "pages": [ … ] }

{
  "pageNumber": 1,
  "kind": "text",                     // drawing | text | table | mixed
  "markdown": "# Лист 1\n\n## Лист дословно (из PDF, в порядке исходника)…",
  "extractedText": "…",
  "trust": {
    "level": "layer",                 // dwg | docx | layer | vlm | none
    "title": "высокая — текст и таблицы взяты из текстового слоя PDF дословно…",
    "warnings": []
  },
  "warnings": [],                     // то же, что pageWarnings задания для этого листа
  "numbers": { "checked": true, "total": 20, "found": 20, "precision": 100.0, "suspect": [] },
  "tables": ["| Обозначение | Наименование |\n|---|---|\n…"],
  "schema": 8
}
```

```jsonc
GET /jobs/{id}   →   { …, "pageErrors": {}, "pageWarnings": {}, "modelPages": 0 }

GET /health      →   { …,
  "queue": { "queued": 5, "processing": 1, "done": 18, "error": 0, "canceled": 0 },
  "currentJobs": { "model": null, "vector": "4e0a8562-…" }
}
```

**Уровни доверия.** `dwg` — текст прочитан из данных чертежа, модель не
вызывалась. `docx` — текст и таблицы прочитаны из файла записки дословно,
модель не вызывалась. `layer` — текст и таблицы взяты из текстового слоя PDF
дословно, моделью написано только «Описание листа». `vlm` — текстового слоя
нет, всё содержимое прочитано по изображению: числа и марки нужно сверять с
оригиналом. `none` — с листа ничего не извлечено.
