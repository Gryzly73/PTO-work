оригиналом. Наше предложение: либо показывать подпись всем, либо оставить её
админу, но для `vlm` выводить отдельную пометку рядом с текстом листа. Само
предупреждение об этом уже придёт в `page.warnings`, так что достаточно не
прятать плашку.

**Зачем.** Сейчас каждый лист подписан «Модель», даже когда модель не
вызывалась вовсе — а у чертежа DWG и у листа с исправным текстовым слоем текст
берётся из данных дословно. Это ровно то различие, ради которого мы вводили
уровень доверия: инженер не должен перепроверять то, что перепроверять не
нужно, и должен перепроверять то, что прочитано по картинке.

### 3. Подозрительные числа — необязательно, но дёшево

**Файлы:** `src/lib/process-document.ts`, `src/components/review-pane.tsx`.

Поле `page.numbers`: мы берём все числа из описания, написанного моделью, и
ищем каждое в текстовом слое и таблицах листа. Не найденные — кандидаты в
галлюцинации. Из текста они не удаляются, только помечаются.

```jsonc

  "total": 20,        // чисел в описании модели

  "precision": 100.0,
  "suspect": []       // не нашлись — вот эти перепроверить
```

**Зачем.** Выдуманная марка насоса от настоящей глазами не отличается — это
главный риск всего проекта. Показать список рядом с текстом листа стоит
вечера, а инженеру даёт точку приложения внимания.

### 4. Перезапуск фронтенда роняет идущие прогоны

**Файлы:** `src/lib/storage.ts` (функция `resetStuckDocuments`, строки
1064–1082) и **два места вызова**: `src/app/api/documents/route.ts:23` и
`src/app/api/documents/kit/route.ts:125`.

Документ считается зависшим, если его нет в множестве `running` — а оно живёт
в памяти процесса Next.js (`process-document.ts:70`). После любого деплоя
фронта множество пустое, и ровно через `STUCK_AFTER_MS` (5 минут, строка 50)
все считающиеся документы получают статус ошибки и текст «Обработка
прервалась. Нажмите „Повтор“». Бэкенд в это время продолжает считать как ни в
чём не бывало.

Утром 28.08 это выглядело так: комплект загружен в 06:18, фронт запулен и
перезапущен, в 06:23 оба документа помечены ошибкой с нулём страниц. Задания
на бэкенде были живы всё это время.

`resetStuckDocuments` **уже возвращает** список id, которые пометил ошибкой,
— сейчас оба вызова этот список выбрасывают. Достаточно его использовать:

```diff
-await resetStuckDocuments(activeDocumentIds());
+const stuck = await resetStuckDocuments(activeDocumentIds());
+for (const id of stuck) {
+  const job = await findPipelineJob(id);          // pipeline.ts:75, уже есть
+  if (job?.status === "processing" || job?.status === "queued") {
+    runInBackground(processDocument(id));         // подхватит через findExistingJob
+  }
+}
```

Правку нужно сделать в обоих местах вызова (или обернуть в общий хелпер).

**Зачем.** Сейчас любой деплой фронта во время работы выглядит для
пользователя как потеря нескольких часов счёта. Данные при этом целы —
«Повтор» подцепляется к тому же заданию и забирает готовое без пересчёта, — но
об этом знаем мы, а не инженер, который видит красное.

### 5. Удаление документа не снимает задание с бэкенда

**Файл:** `src/app/api/documents/[id]/route.ts`, обработчик `DELETE`
(строки 52–62).

`deleteDocument` (`storage.ts:1047`) убирает свою запись, файл и байты PDF — и
всё. Конвейеру никто ничего не говорит, задание остаётся в очереди и

общей папке `uploads`: он исчез, и задание упало само. Это побочный эффект, а
не отмена — задание на файл из другого места считало бы дальше.

```diff
+  const job = await findPipelineJob(id);          // pipeline.ts, уже есть
```

### 7. Имена файлов из ZIP приезжают кракозябрами

**Файл:** `src/lib/drawing-kit.ts` — функция `baseName` (строка 27) и её вызов
в `extractDrawingKitFromZip` (строка 47).

Проводник Windows пишет имена в архив в кодировке cp866 и не ставит флаг UTF-8
(бит `0x800`). `fflate` читает такие имена как latin1, и
«1. Жуковский I _ СП.dwg» превращается в `1. ãª®¢áª¨© I _ .dwg` — с
управляющими символами внутри. Работать не мешает, но выглядит как поломка, и
документ потом не найти поиском.

```ts
// перекодировать имя, если оно состоит из latin1-байтов:
function fixZipName(name: string): string {
  if (!/[\u0080-\u00FF]/.test(name)) return name;   // ASCII или уже UTF-8
  const bytes = Uint8Array.from(name, (ch) => ch.charCodeAt(0) & 0xff);
  return new TextDecoder("ibm866").decode(bytes);   // ibm866 — он же cp866
}
```

**Зачем.** Имя файла — это то, по чему инженер узнаёт лист в списке. Плюс мы
сводим DWG и PDF одного раздела по основной надписи, и читаемое имя источника
идёт в отчёт.

## Как проверить, что заработало

1. **Пункты 1–2.** Загрузить любой PDF с текстовым слоем: у листов должно
   стоять «Авторазбор», а не «Модель». Затем поднять бэкенд в режиме
   `PTO_PIPELINE_MODE=mock` — каждый лист придёт с предупреждением «имитация:
   сервис работал в режиме mock, модель не вызывалась», и оно должно
   появиться и в плашке над текстом, и в `pageWarnings` документа.
2. **Пункт 4.** Запустить обработку большого PDF, перезапустить фронт,
   подождать больше пяти минут: документ должен остаться в обработке, а не
   получить «Обработка прервалась».
3. **Пункт 5.** Удалить документ во время обработки и проверить
   `GET /jobs?documentId=…` на бэкенде — задания быть не должно.
4. **Пункт 7.** Собрать ZIP Проводником Windows из файлов с русскими именами
   и загрузить как комплект: имя DWG в списке должно читаться.
