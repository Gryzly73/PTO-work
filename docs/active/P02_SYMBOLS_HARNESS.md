# P02 — Operational harness распознавания условных обозначений

**Статус:** done (2026-08-24) · **Basket:** S0–S8 · **Runtime gate:** opt-in `PTO_SYMBOLS`  
**Назначение:** довести распознавание легенды и экземпляров обозначений от
воспроизводимого GT до опциональной интеграции, не ломая контракт страницы schema 5.

Актуальное сквозное описание алгоритма, статусов H5/H6, fail-closed контрактов
и ограничений: [Методика распознавания и расшифровки условных обозначений](./МЕТОДИКА_РАСПОЗНАВАНИЯ_И_РАСШИФРОВКИ_УСЛОВНЫХ_ОБОЗНАЧЕНИЙ.md).

## Неподвижные границы

- До S8 основной runtime не подключается и публичный JSON не меняется.
- Координаты хранятся в PDF points; runtime-координаты конкретной страницы не
  зашиваются в код.
- HF, Tesseract и сеть не являются обязательными для тестов и gate.
- Связь экземпляра с типом считается подтверждённой только документом или человеком;
  инженерные связи автоматически не выводятся.
- Неизвестные, несовпавшие и конфликтные сущности сохраняются явно.
- Локальные PDF, crops и customer GT не коммитятся.

## Фикстуры и роли

- Коммитится только синтетический self-check: две строки легенды, два известных
  типа, повтор неизвестного знака и negatives text/table/line-intersection.
- Локальный manifest распределяет: PB — dev; KR1 и ODI — vertical slice;
  KR4 — holdout; KR5 — negative; KR3 — regression/out of KPI.
- KPI вводятся фазами, где появляется соответствующий алгоритм; S0 проверяет
  воспроизводимость метрик, но не заявляет качество на customer data.

## Общий gate

```powershell
python -m pytest -q
python -m symbols.validate_gt --self-check
```

## Правило checkpoint

Каждая фаза обновляет только свой scope после фактической проверки: файлы,
точные команды и результат. Коммит и сетевые вызовы — только по отдельному запросу.
